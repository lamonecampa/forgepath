MODULE 01 / FRAMEWORK BASICS

Mengapa Laravel dan apa prasyaratnya?

Framework menyediakan struktur dan komponen siap pakai agar pengembang tidak perlu merancang ulang routing, validasi, akses database, templating, dan banyak kebutuhan umum. Laravel adalah framework PHP yang mengadopsi pola dan praktik modern.

Jangan mulai Laravel sebelum memahami variabel, fungsi, array, OOP dasar, Composer, HTTP request/response, serta SQL. Tanpa fondasi itu, error framework akan terasa seperti rangkaian mantra, bukan masalah yang bisa dianalisis.

Persiapan lingkungan

  • PHP versi yang didukung oleh Laravel yang dipilih.
  • Composer untuk dependency PHP.
  • Database MySQL atau database lain yang didukung.
  • Node.js dan npm bila proyek memakai build aset frontend.
  • Terminal dan Git.
Versi acuan halaman ini adalah Laravel 13. Periksa persyaratan dan dokumentasi resmi sebelum instalasi. Laravel 13 dirilis pada 17 Maret 2026 dan membutuhkan PHP minimal 8.3. Tutorial Laravel 5.x/8.x/12.x mungkin berbeda dalam struktur file, API, dan konfigurasi. Jangan menyalin perintah lintas versi tanpa verifikasi.
composer create-project laravel/laravel forgepath-app cd forgepath-app php artisan --version php artisan serve

MODULE 02 / PROJECT STRUCTURE

Mengenali struktur proyek

Proyek Laravel memiliki direktori dengan tanggung jawab berbeda. app/ menyimpan kode aplikasi, routes/ mendefinisikan endpoint, resources/views/ menyimpan template Blade, database/ berisi migration dan seeder, sedangkan public/ menjadi document root web.

app/ Http/Controllers/ Models/ bootstrap/ config/ database/ migrations/ seeders/ public/ resources/views/ routes/ web.php storage/ tests/ vendor/

Folder vendor/ dikelola Composer dan biasanya tidak diedit manual. File .env berisi konfigurasi lingkungan dan rahasia; jangan commit ke repository publik. Sediakan .env.example tanpa kredensial asli.

MODULE 03 / ROUTING

Routing dan HTTP methods

Route memetakan URL dan HTTP method ke aksi aplikasi. Gunakan GET untuk membaca, POST untuk membuat, PUT/PATCH untuk memperbarui, dan DELETE untuk menghapus resource. Nama route membantu membuat tautan yang tidak bergantung pada URL hard-coded.

use Illuminate\Support\Facades\Route; Route::get('/mahasiswa', [MahasiswaController::class, 'index']) ->name('mahasiswa.index'); Route::get('/mahasiswa/create', [MahasiswaController::class, 'create']) ->name('mahasiswa.create'); Route::post('/mahasiswa', [MahasiswaController::class, 'store']) ->name('mahasiswa.store');

Route resource dapat menghasilkan pola CRUD standar. Gunakan middleware untuk menerapkan autentikasi atau aturan akses. Jangan menganggap menyembunyikan tombol di tampilan sudah cukup untuk mengamankan endpoint.

Route::resource('mahasiswa', MahasiswaController::class); php artisan route:list
MODULE 04 / MVC & BLADE

MVC, controller, dan Blade view

Dalam pola MVC, Model mengelola representasi data/domain, View menyajikan antarmuka, dan Controller mengoordinasikan request serta respons. Tujuannya memisahkan tanggung jawab, bukan sekadar membuat banyak file.

class MahasiswaController extends Controller { public function index() { $mahasiswa = Mahasiswa::latest()->paginate(10); return view('mahasiswa.index', compact('mahasiswa')); } }

Blade mendukung layout, komponen, directive, dan escaping output. Gunakan {{ $nilai }} untuk output yang di-escape secara default. Sintaks {!! !!} menampilkan HTML mentah dan hanya boleh digunakan untuk konten yang benar-benar dipercaya atau telah disanitasi dengan benar.

@extends('layouts.app') @section('content') <h1>Daftar Mahasiswa</h1> @foreach ($mahasiswa as $item) <p>{{ $item->nama }}</p> @endforeach {{ $mahasiswa->links() }} @endsection
MODULE 05 / DATABASE

Migration, model, factory, dan Eloquent

Migration mendeskripsikan perubahan struktur database dalam kode yang dapat dilacak melalui version control. Eloquent ORM memetakan model ke tabel dan menyediakan API untuk query serta relasi.

php artisan make:model Mahasiswa -m Schema::create('mahasiswa', function (Blueprint $table) { $table->id(); $table->string('nim', 20)->unique(); $table->string('nama', 120); $table->string('email')->nullable(); $table->timestamps(); }); php artisan migrate

Konfigurasi koneksi database berada di environment/config. Model dapat mengatur nama tabel, primary key, casts, dan relasi. Pahami mass assignment: gunakan $fillable atau $guarded secara sadar, bukan membiarkan semua field dapat diisi sembarang request.

$mahasiswa = Mahasiswa::create([ 'nim' => '24001', 'nama' => 'Rani Putri', 'email' => 'rani@example.com', ]); $daftar = Mahasiswa::where('nama', 'like', 'R%') ->orderBy('nama') ->paginate(10);
MODULE 06 / CRUD WORKFLOW

Membangun CRUD lengkap

CRUD memerlukan lebih dari empat query. Rancang alur daftar, detail, formulir tambah, proses simpan, formulir edit, proses pembaruan, dan penghapusan. Berikan redirect dan feedback setelah operasi berhasil.

public function store(Request $request) { $validated = $request->validate([ 'nim' => ['required', 'string', 'max:20', 'unique:mahasiswa,nim'], 'nama' => ['required', 'string', 'max:120'], 'email' => ['nullable', 'email', 'max:160'], ]); Mahasiswa::create($validated); return redirect() ->route('mahasiswa.index') ->with('success', 'Data berhasil disimpan.'); }

Untuk update, aturan unique perlu mengabaikan record yang sedang diedit. Untuk delete, pastikan pengguna berwenang dan pertimbangkan soft delete bila data perlu dipulihkan. Gunakan form method spoofing untuk PUT/PATCH/DELETE dan sertakan token CSRF.

MODULE 07 / SECURITY

Validasi, otorisasi, dan keamanan

Validasi memeriksa apakah input memenuhi aturan. Otorisasi menentukan apakah pengguna tertentu boleh melakukan aksi pada resource. Keduanya berbeda dan sama-sama diperlukan.

  • Gunakan Form Request atau validator untuk aturan input.
  • Gunakan policy/gate untuk mengontrol akses terhadap resource.
  • Jaga CSRF protection untuk form web.
  • Gunakan query builder/Eloquent dan hindari merangkai SQL mentah dari input.
  • Escape output di Blade dan sanitasi konten HTML bila memang diperlukan.
  • Rahasiakan APP_KEY, password database, token, dan kredensial layanan.
  • Gunakan HTTPS dan konfigurasi cookie/session yang sesuai.

Jangan pernah menampilkan stack trace, query, path file, atau konfigurasi rahasia kepada pengunjung production.

MODULE 08 / AUTH & TESTING

Autentikasi, middleware, dan pengujian

Autentikasi memastikan identitas pengguna; otorisasi menentukan haknya. Gunakan starter kit resmi atau mekanisme autentikasi yang sesuai versi Laravel, bukan membangun sistem password sendiri tanpa memahami risikonya.

Middleware dapat membatasi route berdasarkan status login, role, atau kondisi request. Pengujian membantu memastikan alur aplikasi tetap benar saat kode berubah.

php artisan make:test MahasiswaTest php artisan test

Uji setidaknya: halaman dapat diakses, pengguna tanpa izin ditolak, input tidak valid menghasilkan error validasi, data valid tersimpan, update mengubah record yang benar, dan delete tidak menghapus record lain.

MODULE 09 / DEPLOYMENT

Deployment dan pemeliharaan

Deployment memindahkan aplikasi dari lingkungan pengembangan ke server produksi. Pastikan document root diarahkan ke direktori public, bukan root proyek. Folder storage dan cache harus memiliki permission yang tepat, dan file rahasia tidak boleh dapat diakses publik.

composer install --no-dev --optimize-autoloader php artisan config:cache php artisan route:cache php artisan view:cache php artisan migrate --force

Perintah dan proses deployment dapat berbeda menurut hosting dan versi Laravel. Bangun aset frontend bila proyek menggunakannya. Atur environment production, APP_DEBUG=false, HTTPS, backup database, log, queue, scheduler, dan proses rollback. Uji restore backup secara berkala.

Jangan mengunggah folder vendor atau .env ke repositori publik hanya karena tutorial menyuruh mengirim seluruh folder proyek. Ikuti metode deployment yang sesuai platform dan dokumentasi versi yang dipakai.
