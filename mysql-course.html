MODULE 01 / DATABASE BASICS

Memahami database relasional

Database adalah sistem terorganisasi untuk menyimpan dan mengelola data. MySQL merupakan relational database management system (RDBMS): data disusun dalam tabel, dan hubungan antarentitas dinyatakan melalui key.

Contoh sistem akademik memiliki entitas mahasiswa, mata kuliah, dan nilai. Memisahkan entitas membantu mengurangi pengulangan data dan menjaga konsistensi. SQL (Structured Query Language) digunakan untuk mendefinisikan struktur dan mengolah data.

Database: akademik ├── mahasiswa ├── mata_kuliah └── nilai ├── mahasiswa_id → mahasiswa.id └── mata_kuliah_id → mata_kuliah.id
MODULE 02 / DATA MODELING

Entitas, atribut, primary key, foreign key, dan ERD

Mulai desain database dari kebutuhan, bukan dari tebakan nama kolom. Identifikasi entitas, atribut, hubungan, kardinalitas, dan aturan bisnis. Primary key membedakan setiap record; foreign key menghubungkan record ke tabel lain.

Relasi umum: one-to-one, one-to-many, dan many-to-many. Hubungan many-to-many biasanya membutuhkan tabel penghubung (junction table). Contoh mahasiswa mengambil banyak mata kuliah, dan satu mata kuliah diikuti banyak mahasiswa, sehingga dibuat tabel KRS.

mahasiswa (1) ─── (N) krs (N) ─── (1) mata_kuliah

Normalisasi membantu mengurangi redundansi dan anomali insert/update/delete. Pahami minimal bentuk normal pertama sampai ketiga pada skema sederhana, tetapi tetap pertimbangkan kebutuhan query dan performa.

MODULE 03 / SETUP & SQL

Menyiapkan MySQL dan mengenal SQL

Untuk belajar lokal, gunakan MySQL Community Server atau paket seperti XAMPP/Laragon. phpMyAdmin adalah antarmuka administrasi berbasis web, bukan mesin database itu sendiri. Buat database latihan terpisah dan gunakan akun dengan hak akses terbatas.

CREATE DATABASE akademik CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; USE akademik; SELECT VERSION();

SQL memiliki kelompok perintah seperti DDL (CREATE/ALTER/DROP), DML (INSERT/UPDATE/DELETE), dan DQL (SELECT). Hak akses dan transaksi juga memiliki perintah khusus. Jalankan perintah pada database latihan terlebih dahulu.

MODULE 04 / TABLE DESIGN

Membuat tabel dan memilih tipe data

Pilih tipe data sesuai makna dan rentang nilai. Contoh: INT untuk bilangan bulat, VARCHAR untuk teks dengan panjang terbatas, TEXT untuk teks panjang, DATE untuk tanggal, DATETIME untuk tanggal dan waktu, DECIMAL untuk nilai numerik presisi tetap seperti nominal uang.

CREATE TABLE mahasiswa ( id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, nim VARCHAR(20) NOT NULL UNIQUE, nama VARCHAR(120) NOT NULL, email VARCHAR(160) UNIQUE, tanggal_lahir DATE NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

Gunakan constraint seperti NOT NULL, UNIQUE, DEFAULT, CHECK (sesuai versi), PRIMARY KEY, dan FOREIGN KEY untuk menjaga integritas di level database. Jangan menyimpan angka telepon sebagai integer karena nol di depan dan tanda + merupakan bagian dari representasi.

MODULE 05 / CRUD

Operasi dasar: INSERT, SELECT, UPDATE, DELETE

CRUD adalah siklus utama pengelolaan data. Biasakan menyebut kolom secara eksplisit saat INSERT dan selalu periksa kondisi WHERE sebelum UPDATE atau DELETE.

INSERT INTO mahasiswa (nim, nama, email) VALUES ('24001', 'Rani Putri', 'rani@example.com'); SELECT id, nim, nama FROM mahasiswa; UPDATE mahasiswa SET email = 'rani.p@example.com' WHERE nim = '24001'; DELETE FROM mahasiswa WHERE nim = '24001';
UPDATE atau DELETE tanpa WHERE dapat memengaruhi seluruh baris tabel. Sebelum eksekusi, jalankan SELECT dengan kondisi yang sama untuk memastikan targetnya benar.
MODULE 06 / QUERYING

Filter, pengurutan, agregasi, dan pagination

Gunakan WHERE untuk menyaring baris, ORDER BY untuk mengurutkan, LIMIT untuk membatasi hasil, dan fungsi agregat untuk meringkas data. GROUP BY mengelompokkan baris, sedangkan HAVING menyaring hasil agregasi.

SELECT jurusan, COUNT(*) AS jumlah FROM mahasiswa WHERE status = 'aktif' GROUP BY jurusan HAVING COUNT(*) >= 5 ORDER BY jumlah DESC LIMIT 20;

Fungsi agregat yang umum: COUNT, SUM, AVG, MIN, MAX. Untuk pagination berbasis OFFSET, perhatikan biaya pada data sangat besar; strategi keyset pagination dapat lebih efisien untuk navigasi berurutan.

MODULE 07 / JOINS

Menggabungkan tabel dengan JOIN

JOIN mengambil informasi yang tersebar pada tabel terkait. INNER JOIN hanya mengembalikan pasangan yang cocok; LEFT JOIN mempertahankan seluruh baris dari tabel kiri meskipun tidak memiliki pasangan di kanan.

SELECT m.nim, m.nama, k.nama_mk, n.nilai FROM nilai AS n INNER JOIN mahasiswa AS m ON m.id = n.mahasiswa_id INNER JOIN mata_kuliah AS k ON k.id = n.mata_kuliah_id ORDER BY m.nama;

Gunakan alias agar query lebih ringkas, dan pastikan kondisi ON menghubungkan kolom yang benar. JOIN yang salah dapat menggandakan baris atau menghasilkan kombinasi yang tidak masuk akal.

MODULE 08 / INTEGRITY & PERFORMANCE

Relasi, transaksi, indeks, dan optimasi

Foreign key menjaga agar referensi antar tabel tetap valid. Transaksi mengelompokkan beberapa operasi menjadi satu unit kerja. Sifat ACID mencakup atomicity, consistency, isolation, dan durability.

START TRANSACTION; UPDATE rekening SET saldo = saldo - 50000 WHERE id = 1; UPDATE rekening SET saldo = saldo + 50000 WHERE id = 2; COMMIT; -- Gunakan ROLLBACK jika proses harus dibatalkan.

Indeks mempercepat pencarian dan join pada kolom yang tepat, tetapi menambah biaya penyimpanan dan operasi tulis. Gunakan EXPLAIN untuk membaca rencana eksekusi, lalu ukur sebelum menambah indeks. Hindari mengindeks semua kolom tanpa alasan.

MODULE 09 / PHP INTEGRATION

Menghubungkan PHP dengan MySQL

Gunakan PDO atau MySQLi dengan prepared statement. Kredensial database harus disimpan di konfigurasi lingkungan, bukan ditanam dalam repository publik. Akun aplikasi sebaiknya hanya memiliki hak yang diperlukan.

$stmt = $pdo->prepare( 'SELECT id, nama FROM mahasiswa WHERE nim = :nim' ); $stmt->execute(['nim' => $nim]); $mahasiswa = $stmt->fetch(PDO::FETCH_ASSOC);

Prepared statement melindungi parameter nilai dari injeksi SQL, tetapi nama tabel/kolom dinamis tetap perlu whitelist karena identifier tidak dapat diperlakukan seperti parameter nilai biasa. Escape output HTML secara terpisah dengan htmlspecialchars().

MODULE 10 / SECURITY & SCALE

Keamanan, backup, dan data besar

Keamanan database bukan hanya soal password. Batasi akses jaringan, gunakan akun terpisah, perbarui server, aktifkan backup teruji, audit hak akses, dan jangan menampilkan error SQL internal kepada pengguna.

  • Gunakan parameterized query untuk input pengguna.
  • Jangan menyimpan password aplikasi dalam source control.
  • Gunakan TLS bila koneksi melintasi jaringan yang tidak dipercaya.
  • Backup harus diuji dengan proses restore, bukan sekadar melihat file dump.
  • Gunakan pagination dan pilih kolom yang dibutuhkan, hindari SELECT * pada query produksi yang tidak perlu.

Untuk data besar, periksa query plan, indeks, ukuran result set, dan pola akses. Optimasi berbasis pengukuran, bukan asumsi.
